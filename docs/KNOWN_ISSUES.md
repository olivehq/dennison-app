# Known issues and deferred work

Findings from the October 4 and October 16, 2026 reviews that were not fixed in the build, with the reason. Each is a candidate for the next change order or the annual readiness pass.

## Deferred, low risk

| Area | Issue | Why deferred |
|---|---|---|
| Tests | 46 tests across 9 server test files depend on running in file order (`pnpm exec vitest run --sequence.shuffle` fails). The default order is stable and `pnpm test` is green. | Rewriting the fixtures per test is a day of work with no behaviour change. Do it when a module is next touched. |
| UI | The timeline blocks and clock controls use raw `button` elements, not the shadcn `Button`, because they need absolute positioning and bespoke treatment. | Documented exception in `docs/ARCHITECTURE.md`. |
| UI | The runs table on the matching page and the activity log use the plain `Table`, not the `DataTable` wrapper. | Both lists are short and have their own filters. Switch if they grow. |
| UI | Cmd-K exists in the schedule workspace only. Other pages have search inputs. | The scope's "everywhere" is best served by the workspace, where names matter most. |
| UI | The upload card and unlock-reason inputs are plain forms, not react-hook-form with `Field`. | Single-field forms; the error display is the same. |
| Tokens | Link expiry is a constant (60 days after the event, or 60 days from issue if later), not an event setting. | No requirement to change it per event yet. Add to settings when asked. |
| Rate limit | The participant-page limiter trusts `x-real-ip` and the first `x-forwarded-for` value. On Vercel these are set by the platform. | On any other host, put the app behind a proxy that overwrites those headers. |
| Exports | GET export routes write an audit row, so a cross-site top-level GET could add a misleading "generated by" row. | Needs a signed-in admin's browser; the row is informational only. |
| Engine | The 2025 regression test uses synthetic data. The real 2025 preference files are due from D&A on October 6, 2026. | Blocked on the files. Add them to `fixtures/` and the regression test when they arrive. |
| Email | A send marks its campaign `failed` when delivery throws or when its closing write fails (a separate transaction, with the reason in the audit row), and a resend puts its status back in a `finally`. A process kill between the claim and either of those, or a database outage that also fails the fallback write, leaves it `sending`. That blocks unlock and archive for the event until the row is fixed by hand. Retention marks a campaign `sending` for more than 6 hours `failed` and goes ahead, so it is delayed by at most a day, not blocked. If the database also fails the write that marks a batch the provider refused as `failed`, those messages stay `queued` with their hand-off time, and "Resend to bounced" skips them because it can't tell them from accepted ones. | Give unlock and archive the same 6-hour stale check if a stuck send happens in practice. The refused-batch case needs the provider and the database to fail together; send those people a campaign with a selected audience. |
| Exports | "Withdrawn on" in the participant and supplier full lists is blank for anyone withdrawn without a withdraw audit row (for example, by an import). There is no stored withdrawal date. | Needs a schema column. Add one if D&A rely on it. |
| Imports | If every file of a kind is ignored, that kind's upload card says "No file uploaded yet", even though the files are still in history. | Cosmetic. |
| Email | A campaign that stopped partway is marked `failed`, so it does not count as "Last email sent" (D126) even if some messages went out. | Waiting on D&A's preference. |
| Settings | Making supplier categories generic (a category per supplier, with minimums and cutoffs per category) is not built. | D&A marked it as later in the October 15 review. |
| Schedule | A refresh that Next itself triggers, or the conflict-error refresh, could still reload a slightly older URL. | Rare after D115. The cost is lost filters, not lost data. |

## Operational notes

- `pnpm db:seed` refuses to run against a remote database unless `SEED_ALLOW_REMOTE=1`. The demo admin password is public; never seed production.
- The Vercel build command in `vercel.json` runs migrations before `next build`. A failed migration fails the deploy.
- `pnpm e2e` starts its own `next dev` on port 3400. Next.js 16 refuses a second dev server in the same folder, so stop `pnpm dev` first.
